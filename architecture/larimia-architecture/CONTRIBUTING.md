# Contributing

## Architecture Changes

Any cross-cutting architecture change requires an ADR under `docs/adr/`.

## Documentation Style

- Keep diagrams in Mermaid unless another format is required.
- Keep business rules explicit.
- Do not duplicate rules across documents unless required for local clarity.
- Link back to the authoritative document.

## Commit Style

Recommended Conventional Commits:

```text
feat:
fix:
docs:
refactor:
test:
chore:
security:
```
